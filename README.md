# D&D Builder

Офлайн-конструктор персонажей D&D 5e (редакция 2014) на русском языке.

## Запуск

Откройте `dnd_builder.html` в современном браузере. Установка и сервер не нужны — приложение работает локально. На вкладке «Лист» можно выбрать оформление 2014 или 2024; расчёты персонажа остаются по правилам 2014 года.

Данные персонажей хранятся в браузере. На странице «Герои» можно скачать резервную копию всей библиотеки и восстановить её из JSON; импорт резервной копии заменяет текущую библиотеку после подтверждения. В редакторе кнопка «JSON» выгружает файл для повторного импорта в конструктор, «LSS» выгружает JSON в формате сайта Long Story Short, «Foundry» — Actor JSON для Foundry VTT.

Оба оформления листа печатаются в четырёхстраничном формате A4. Лист и экспорты персонажа блокируются, пока не заполнены обязательные выборы и не исправлены ошибки; черновик можно сохранить и включить в резервную копию. Поля, которых нет в модели персонажа (например, возраст и внешность), оставлены пустыми для ручного заполнения.

Автоматические расчёты покрывают только явно поддержанные правила. Описания классовых/подклассовых особенностей и черт не означают, что их эффекты полностью применены; интерфейс отмечает поддержанные эффекты черт, остальные эффекты нужно учитывать вручную.

Каталог включает добавленные варианты редакции 2014 года: 72 расы/вида, 53 подрасы/варианта и 47 подклассов для поддерживаемых классов. Их новые особенности показаны как справочный текст, с метками источников сайта; эффекты, не поддержанные автоматизацией, нужно учитывать вручную. Состав и исключения описаны в [CONTENT_SOURCES.md](CONTENT_SOURCES.md).

## Foundry VTT

Кнопка «Foundry» экспортирует Actor JSON для **Foundry VTT 12 и системы dnd5e 3.3.1**. Экспорт включает характеристики, владения, ресурсы, классы/подклассы, выбранные заклинания, черты и инвентарь. Черты и особые выборы переносятся описаниями; они не превращаются автоматически в эффекты правил Foundry. Экспорт не является универсальным форматом для других версий Foundry или dnd5e.

## Проверки

Запустите регрессионные тесты расчётов командой `node --test tests/rules.test.cjs` (Node.js, без сторонних зависимостей). Сводку источников можно получить командой `node scripts/audit-content-sources.cjs`.

## iOS PDF smoke test

На Mac с Xcode и запущенным iOS Simulator выполните `tests/ios_pdf_export.sh` (можно передать UDID; PDF сохраняется в `/tmp/dnd-builder-ios-sheet.pdf`, путь меняется через `IOS_PDF_OUTPUT`). Тест прогоняет лист 2014 через iOS WebKit и системный `UIPrintPageRenderer`, создаёт PDF и проверяет четыре страницы с содержимым. На текущем iOS 27 WebKit добавил пятый пустой хвостовой лист; тест учитывает его отдельно. Это проверка PDF-рендеринга WebKit, не автоматизация кнопки печати/диалога «Сохранить в Файлы» в Safari.

## Исходники и сборка

Пользовательская версия остаётся одним автономным файлом `dnd_builder.html`. Исходники разнесены по `src/`: шаблон, стили, игровые данные, чистые расчёты правил, ядро хранения, изменения состояния персонажа, предметная валидация и интерфейс. Каталоги заклинаний и дополнительных данных редакции 2014 хранятся отдельно в `data/` и встраиваются при сборке. После правок пересоберите HTML командой `node scripts/build.cjs`; тесты проверяют, что готовый файл соответствует исходникам.

Браузерные проверки запускаются отдельно: `node tests/browser_backup_restore.mjs` проверяет сохранение после перезагрузки, импорт и восстановление резервной копии, отклонение заклинания не из списка класса, выбор владений и предупреждения о доспехах, XSS-защиту и сохранность повреждённой библиотеки до явного восстановления из копии (нужен Chrome/Chromium; путь можно задать через `CHROME_BIN`).

## Источники данных

В приложении есть материалы SRD 5.1, PHB, «Котла Таши», AAG и других книг редакции 2014, а также данные заклинаний из нескольких источников. Состав, атрибуция и незакрытые вопросы по происхождению описаны в [CONTENT_SOURCES.md](CONTENT_SOURCES.md); не весь контент подтверждён как SRD.
